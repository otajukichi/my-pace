# Googleログインから、自分の記録を開く

2026-11-17追記：本番のGoogleログイン・4件表示・再読み込み・ログアウトは利用者の実機確認で成功。次は [継続取り込みの導入](gas/PRODUCTION.md)。以下は接続設定の資料であり、設定済みの方はやり直さなくてよい。

2026-11-16の接続実装。接続先は **MyPace共通管理フォルダ内の `running/derived/index.json`** に固定。目次名を指定する `MYPACE_DRIVE_CATALOG` は廃止した。右上のアカウントメニュー、通常URL、ログイン後の自動表示はそのまま使う。2026-11-13の `NEW_CSV_PASS` を引き継ぐ。**12段階・24時間監視・新CSV取り込みを再実行する必要はない。** 既存のApps Scriptコード・プロパティ・キャッシュ・トリガー・元CSVを変更しない。

## 今回できること

通常の `/#records` を開くとログイン状態を確認し、ログイン済みなら本人のDriveデータを自動で表示する。右上のアカウントアイコンからGoogleログイン・設定・記録の再読込み・ログアウトを行う。ログイン直後も通常URLへ戻り、表示方式を選ぶ必要はない。

未ログイン時はログイン案内を表示し、個人のランニング記録を取得しない。通信障害は未ログインとは区別して再試行できる。ログアウト時には表示中のDrive記録を消し、ほかの開いているタブへも通知する。通信中に遅れて届いた記録も復活させない。

「ローカル／Driveプレビュー」は **アカウント → 設定 → 接続の確認（検証用）** に残す。通常画面のヘッダーには出さない。公開ビルドの静的データは引き続き空。既存のカレンダー・ルート概形・集計・速度付き地図・RUNNING LOG・探索済み範囲・新しく走った距離の表示を使う。

**今回、日記・名前・配色はまだブラウザー内だけに保存する。Driveへの書込み、自動同期、端末間共有は未実装。** アカウント画面にもこの状態を明記し、送信機能がない状態で「同期待ち」「同期済み」とは表示しない。

```text
既存検証の derived（完成済みJSON・そのまま残す）
  └─ 完成JSONをコピーし、合格した目次を index.json にする
       → MyPace管理フォルダ / running / derived / index.json
                                      ↓ 読み取りのみ
Googleログイン → Vercel Functions → MyPaceの現在の画面
```

- Googleの公式認証ライブラリでコード交換・IDトークン検証。state・nonce・PKCEを使用。
- ログイン時は共通管理フォルダの所有・非共有状態を確認。別アカウントは拒否。ランニング読込み時は共通フォルダ、`running`、`derived`、対象JSONの所有・非共有状態と配置を確認する。
- Googleトークンは暗号化したHttpOnly Cookieに保持。ブラウザーのJSやlocalStorageへ渡さない。セッションは最長30日、Google側で失効した場合は再ログイン。
- APIが受け付けるのは `index.json` と `objects/<SHA-256>.json` のみ。Drive ID、CSV、任意の機能フォルダの指定は不可。共通フォルダ内の `running/derived` だけから本文を読む。
- 内容ハッシュで固定されたファイルはSHA-256を照合。本文は128KiB以下。応答は `private, no-store`、CDNにも保存しない。GPS・トークン・Googleのエラー本文をサーバーログへ出さない。
- 履歴・概形は軽い一覧から取得。日別は選んだ日の経路、月別は月の軽量経路、分析は詳細を開いたとき、探索マスクは表示範囲のブロックだけ取得。キャッシュはブラウザーのメモリー内。地図の探索・新しい道を生CSVから再計算しない。
- CSV変換・Drive書き込み・Apps Scriptの起動を行うAPIは追加していない。画面を開くための初回全件CSV処理はない。

### フォルダの探し方と通信量

サーバーは `MYPACE_ROOT_FOLDER_ID` の直下から、名前が完全一致する `running` → `derived` をたどる。各段階で検索対象を親フォルダに限定し、必要なメタデータだけ取得する。Drive全体の走査やCSVの内容確認はしない。Google APIの [親・名前による検索](https://developers.google.com/workspace/drive/api/guides/search-files) と [所有・共有・親情報](https://developers.google.com/workspace/drive/api/reference/rest/v3/files) を使う。

表示ファイル1件をサーバーから取得する際、Driveへの要求は通常 **5回**（共通フォルダ確認1回、子フォルダ特定2回、対象ファイル特定1回、軽量JSON取得1回）。従来の3回に対し小さなメタデータ要求が2回増える。フォルダの許可判定を長期間キャッシュせず、移動・改名・共有変更を次の取得時に反映する。同名フォルダの重複、不完全な検索結果、ショートカットは拒否し、旧接続先や別の場所へ自動で探しに行かない。取得済み表示データのブラウザー内メモリーキャッシュは維持する。

機能別のフォルダID設定は不要。将来の `english` や `app/diary` もこの共通ルートを基準にできるが、今回はそれらを読むAPIや保存処理は追加していない。

### 正式な目次と更新順序

アプリが読む目次は **`running/derived/index.json` の一つだけ**。環境変数で別名へ切り替えず、検証用の目次へ自動で戻る処理も持たない。`index.json` が欠けたり同名ファイルが複数あったりすれば、データを選び直さずエラーを表示する。

将来の自動更新でもこの名前を維持する。先に参照先のハッシュ名JSONをすべて保存・確認し、最後に `index.json` の内容を更新する。途中で処理が止まった場合は前回の正常な目次を残す。既存の生成・配信処理にもこの順序がある。今回、アプリからの書込みや新しい出力先への自動同期は追加していない。

## あなたの操作：初回だけ

### 1. Driveに共通フォルダを用意して完成データをコピー

検証に使ったGoogleアカウントの **マイドライブ** に、次の3フォルダを作る。最上位の名前は自由。内側の `running` と `derived` は小文字でこの名前にする。同じ場所へ同名フォルダを複数作らない。

```text
MyPace管理フォルダ  ← Vercelに登録するのは、このフォルダのID
└─ running
   └─ derived
      ├─ index.json  ← 最新の正常な目次
      ├─ <64文字のハッシュ>.json
      └─ …完成済みのJSON一式
```

`running/system`、`english`、`app/diary`、`app/settings` は将来用なので、今回は作らなくてよい。原本CSVの保管場所も変えない。

1. 新しい3フォルダは自分の所有にする。共有画面で **一般的なアクセス：制限付き、アクセスできるユーザー：自分のみ** を確認する。他者を追加したり、リンク共有を有効にしたりしない。
2. 既存の **「MyPace 差分更新検証 … / derived」** を開く。処理は完了済みなので、Apps Scriptを動かさず、その中の完成済み `.json` ファイルを全部選んで **ダウンロード** する。
3. ダウンロードされたZIPをPC上で展開する。**展開したコピーの中で**、古い `index.json` をアップロード対象とは別の場所へ退避し、合格済みの **`new-csv-index.json` を `index.json` に改名** する。中身は編集しない。元のDriveにあるファイルは改名しない。
4. 新しい `MyPace管理フォルダ/running/derived` に、まず長いハッシュ名の `.json` ファイルをすべてアップロードし、完了後に上記で改名した **`index.json` を最後にアップロード** する。すべて `derived` の直下に置く。ZIPやさらに内側のフォルダをアップロードしない。概形、地図、分析、探索範囲、新しく走った道はこの一式に含まれる。ハッシュ名JSONの名前・内容は変えず、目次も中身は変えない。
5. 一番上の **MyPace管理フォルダ** を開き、URLの `folders/` の後ろにあるIDを控える。`running` や `derived` のIDと取り違えない。URLに `?` 以降があれば、その部分は含めない。

**前の手順ですでにコピー済みの場合は、ダウンロードからやり直さなくてよい。** 新しい `running/derived` のJSON群が揃っている状態で、その中の古い `index.json` があれば `previous-index.json` など未使用の別名へ退避し、`new-csv-index.json` を `index.json` に改名する。これで合格済みの目次の内容を引き継げる。`index.json` は必ず一つにする。操作するのは新しいコピー先だけで、既存の検証フォルダはそのまま残す。

ブラウザーの「コピーを作成」では名前に「のコピー」等が付くため、今回はダウンロード・展開・アップロードでハッシュ名を保つ。ショートカットは使えない。JSONにも個人のGPSが含まれるので、ダウンロードした一式をGitHubや公開サイトへ置かない。

**この引き継ぎは、完成済みデータを画面につなぐためのコピー。今後のApps Scriptの更新がコピー先へ自動反映されるわけではない。** 今回は処理済みキャッシュを移動せず、Apps Scriptの出力先やトリガーも変更しない。継続運用の出力先を新構造へ切り替えるときに、利用者と確認して変更する。画面接続のためにCSVを再処理する必要はない。

### Google認証の設定がまだない場合だけ

既にWeb用OAuthの設定が済んでいれば、この節は飛ばす。今回のフォルダ構造変更で **Google Cloudの設定・同意する権限・リダイレクトURIを変える必要はない**。未設定の場合は、利用者が以下を行う。既存のGoogle Cloudプロジェクトを使え、Apps Scriptの関連付けを変える必要はない。

1. Google Cloudで **Google Drive API** が有効か確認する。課金アカウントや有料サービスの追加は不要。
2. Google Auth Platformの対象は個人Gmailなので **External**。まずTestingの場合は、Driveのフォルダを所有するアカウントをテストユーザーに入れる。
3. データアクセスは `openid`、メール、`https://www.googleapis.com/auth/drive.readonly`。このGoogle権限自体はDrive全体の読取権限であることを確認して同意する。アプリの実装では共通フォルダ内の決められた配置だけを読む。既存・手動コピーの完成ファイルなので、`drive.file` だけではそのまま読めない。[Driveの権限](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)
4. クライアント種類 **ウェブアプリケーション** を作る。既存の適切なWebクライアントがあれば再利用できる。リダイレクトURIを `https://現在のMyPaceのドメイン/api/google-auth` にする。URL末尾・プロトコル・ドメインを完全一致させる。ローカルでも使うなら `http://127.0.0.1:4173/api/google-auth` を追加する。
5. クライアントIDとシークレットを次の環境変数へ保存する。GitHubやチャットへ貼る必要はない。

Testingのままだと、このDrive権限ではGoogleの更新トークンは7日で失効する。継続利用ではOAuthの公開ステータスをIn productionにすることで、このTesting固有の7日制限を外せる。本人専用は審査免除の対象だが未確認アプリの警告が出る場合がある。OAuthの公開ステータスを変えても、Driveの共有設定やアプリの所有者制限は変わらない。[トークンの期限](https://developers.google.com/identity/protocols/oauth2#expiration)、[個人利用の扱い](https://developers.google.com/identity/protocols/oauth2/production-readiness/brand-verification#personal-use)

### 2. Vercelに接続設定を保存

Vercelで現在の **my-paceプロジェクト → Settings → Environment Variables** を開く。普段のURLを使う場合は **Production** を対象にして、以下を設定する。Hobbyのまま使う。既にある認証情報・URL・秘密値はそのままでよい。Previewにも設定する場合、GoogleのリダイレクトURIと `MYPACE_ORIGIN` にその環境の固定ドメインを用いる。

| 変数 | 値 |
| --- | --- |
| `MYPACE_ORIGIN` | 実際のMyPaceのURLの先頭部分。例 `https://your-project.vercel.app`。末尾 `/` なし |
| `GOOGLE_CLIENT_ID` | Web用OAuthクライアントのID |
| `GOOGLE_CLIENT_SECRET` | そのシークレット |
| `MYPACE_SESSION_SECRET` | 32文字以上のランダムな秘密値 |
| `MYPACE_ROOT_FOLDER_ID` | **新しいMyPace管理フォルダ** のID。`running` や `derived` のIDではない |

旧 `MYPACE_DRIVE_FOLDER_ID` はこの版では使わない。旧版への切り戻し用に値を自分だけの場所へ控えてから、Vercelの設定を新しい変数へ置き換える。**変数名だけ変えて旧 `derived` のIDをそのまま使うのは不可。** 新しい値は上記で用意した共通管理フォルダのIDにする。

**`MYPACE_DRIVE_CATALOG` は登録しない。既に登録した場合は削除して再デプロイする。** 新版はこの変数を参照しないので、旧値が残っていても読込先は常に `index.json` になる。目次の名前を指定する代わりの環境変数もない。

新しい環境変数を設定して再デプロイするまでは、通常画面は接続未設定の案内になる。旧フォルダへ自動的に戻って読み込むことはない。

設定を保存したら **Deployments → 今回の変更を含む最新のmainのデプロイ →「…」→ Redeploy → Productionを確認して実行**。状態が **Ready** になったら、以前と同じMyPaceのURLを開く。環境変数の変更は既存デプロイへ自動反映されないため、再デプロイが必要。[環境変数の更新](https://vercel.com/docs/environment-variables/managing-environment-variables)、[再デプロイ](https://vercel.com/docs/deployments/managing-deployments#redeploy-a-project)

ローカルの既存 `.env.local` は今回書き換えていない。ローカルでも接続を試す場合だけ、新しい `MYPACE_ROOT_FOLDER_ID` を設定し、使わなくなった `MYPACE_DRIVE_CATALOG` の行を削除する。旧変数に入っている `derived` のIDを共通フォルダIDへ流用しない。既存の秘密値・認証設定は保持する。このファイルはGit・静的ビルドの対象外。

別のチェックアウトでは `.env.example` を `.env.local` へコピーして設定する。秘密値はパスワード生成ツールなどで作る。ローカル起動は `npm ci` → `npm start`。**Vercelで使うときにPCを起動しておく必要はない。** Vercel Functionsはアクセス時だけ動き、Hobbyの無料枠を使う。有料プラン・常駐サーバー・外部DB・Cronは追加していない。[Vercel Functionsの枠](https://vercel.com/docs/functions/limitations#cost-and-usage)

### 3. 一度の操作で接続を確認

Google側の接続確認はまだ利用者が実施していない。上の設定を済ませ、次の流れを一度通せばよい。**Apps Scriptの再実行・新CSVの追加・24時間の待機は不要。** 旧版で検証用の目次に接続していたログインは無効になるため、最初の一度は再ログインする。

1. MyPaceの通常URL **`/#records`** を開く。右上の **アカウントアイコン → Googleでログイン** を選び、記録のフォルダを所有するGoogleアカウントで同意する。
2. 自動でランニング記録が出ることを確認する。現在の完成データなら **実記録4件**。ルート概形から日を選び、地図・距離・新しく走った道の距離・明るい探索範囲を見る。続けて月全体と詳細の開閉も見る。
3. ブラウザーを再読み込みする。表示方式を選ばず、自分の記録が再表示されればよい。
4. **アカウント → ログアウト**。ランニング記録が消えてログイン案内になることを確認する。日記や設定を消す操作はしない。
5. ローカル方式を確認したい場合だけ、**アカウント → 設定 → 接続の確認（検証用）→ ローカル**。同じ場所の **通常表示（自動）** で戻せる。公開版のローカル方式は空データなので、空になるのが正常。

以前のローカル画面にあった全件を取り込んだわけではない。前の3CSVと今回の1CSVの完成結果を表示する。検証用の人工記録1件は、その固定IDだけを履歴から除外する。今回の目次名統一でも、データの内容は変えていないため、この互換処理は残している。正式な継続更新への移行時に、人工記録を含まない出力とともに外す対象となる。Googleの検証用カタログには人工記録の探索マスクも残っているが、実記録周辺の表示には関係しない。今回の接続のために再計算する必要はない。

端末間での日記同期やオフラインからの送信は、今回の確認対象にしない。まだ送信機能を実装していないため、別端末に日記が出ないことを不具合とは判定しない。

### 結果の返し方

以下を埋めて返せば十分。失敗した場合だけ、止まった操作とエラー文を添える。GPS画像・メール・Drive ID・秘密値は不要。

```text
通常URLからGoogleログイン：できた / できない
ログイン後の自動表示：できた / できない
地図・履歴・集計・探索範囲・新しい道の距離：表示された / 気になる箇所あり
再読込み後の自動表示：できた / できない
ログアウト後に記録が消える：できた / できない
気になる箇所・エラー文：
```

「Google接続の初回設定がまだ完了していません」なら `MYPACE_ROOT_FOLDER_ID` を含む環境変数を設定して再デプロイ。「接続を確認できませんでした」なら通信を確認して再試行。別アカウント・フォルダ権限のエラーならフォルダ所有者のアカウントと設定先を確認する。`running/derived` が見つからない・一つに特定できない場合は階層・名前・同名フォルダの重複を確認。表示用ファイルのエラーならJSON一式の不足や名前変更がないか確認する。権限を広げたりCSVを作り直したりする必要はない。

## 切り戻し

アカウント → 設定 → 接続の確認（検証用）→「ローカル」、または `/?source=local#records` を開く。従来の `data/running.json` 読込へ戻り、Driveの応答を使わない。公開版では空データ、元のPCでは元のローカルデータになる。ブラウザーに保存済みの日記・配色は保持する。通常URLへ戻れば再びログイン状態に応じた表示になる。Googleとのログインを終了する場合は「アカウント → ログアウト」。Cookieを削除し、メモリー内のDrive記録を破棄する。明示的にローカル方式を選んだPCでは、従来のローカルファイルを表示する。

接続機能そのものを止める場合はVercelで `MYPACE_ROOT_FOLDER_ID` を外して再デプロイする。セッション秘密値の変更も既存セッションを無効にする。Googleの原本・表示用データ・キャッシュへ復旧操作は不要。

共通フォルダ化の前のDrive読込コードへ戻す必要がある場合は、旧 `MYPACE_DRIVE_FOLDER_ID` に控えておいた既存検証用 `derived` のIDを再設定し、VercelのDeploymentsから **`1333ba7` の版を再デプロイ** する。旧Google OAuth設定とURLはそのまま使い、再ログインする。元の `derived` を残すため、この切り戻しにデータ移動・再変換は必要ない。これは緊急時の手順で、通常の画面接続確認で実行する必要はない。

## 過去の大量CSVと日次枠

今回の接続は完成データを読むだけなので、Apps Scriptの変換時間枠を消費しない。過去分の取り込みと今後の更新には [継続処理](gas/PRODUCTION.md) を導入する。日ごとの内部予算・途中保存・自動再開を用意した。

個人アカウントのトリガー総実行時間は90分／日、1実行は6分。枠はユーザー単位で共有され、単純な午前0時リセットではなく最初の要求から24時間。Googleの残量は内部計測値から厳密には求められない。[Googleの割り当て](https://developers.google.com/apps-script/guides/services/quotas)

大量取り込みは、監視込みの内部予算を余裕を持って設定し、超える前に途中状態を保存して再開を予約する方式が適する。新しい記録を優先し、過去分を順次追加できる。ただし過去分が加わると「新しく走った道」の基準も変わるので、関連する後続記録の集計も更新する。この運用スケジューラーは読み取り接続とは別の [本番ホスト](gas/production-host.gs) に追加した。Google上ではまだ有効化していないため、導入手順の開始操作を行うまでは日々の自動更新は始まらない。

## 合意した完成形と、次の実装

正式な保存先はGoogle Drive。日記・設定の編集は端末へ先に保存し、未送信の変更を保持して、通信できるときにDriveへ送る。別端末でも同じデータを使う。通常のUIはアカウントアイコンにまとめ、保存先の切替を意識させない。

ランニングの継続更新を導入した後、将来は日記・設定の **端末保存、変更の送受信、未送信の保持・再試行、状態表示、同じ日記を別端末で編集した場合の扱い** を一まとまりで実装する。既存のローカル編集をDriveの内容で無条件に上書きしない。未同期の編集はアカウントに紐づけ、ログアウトで捨てたり別アカウントへ送ったりしない。最初は衝突した両方を残して選べる形を基本案とする。

アプリ使用中の通信復帰と、次に開いたときの同期を基本にする。閉じている間の即時同期は保証せず、オフラインで開き直せる仕組みもこの段階で検討する。軽い編集内容は認証付きAPIからDriveへ送り、CSV変換のApps Scriptとは別に動かす。Googleの書込み権限はその実装時に必要な範囲で追加し、現在の読取り権限は今回変更しない。Vercel Hobby・Googleの無料枠・PC常駐なしを維持する。
