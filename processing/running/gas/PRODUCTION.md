# ランニングの継続取り込みへ移行する

2026-11-18更新。CSV入力は **`my-pace/running/raw` 以下**、設定は **共通ルートIDひとつ**に統一。前版の「入力は共通管理フォルダの外側」という制限を撤回した。

本人認証付きの本番画面・4件の表示・再読み込み・ログアウト確認まで完了した状態から進める。**合格済みの12段階・24時間監視・新CSV検証は繰り返さない。** この文書は新しい継続処理の導入手順。Google上での切り替えは利用者が行う。

## できるようになること

- `running/raw` を約5分ごとに確認する。その配下のサブフォルダも対象。追加・内容変更・改名・移動・削除を、まずサイズ・MD5などのメタデータで判定する。
- 未変更CSVの本文は取得しない。検証用コピーと原本でDrive IDが違っても、サイズ・MD5が一致する処理済みキャッシュを引き継ぐ。
- 未処理の過去CSVも、新しいCSVも同じ処理で取り込む。変更日時が新しいものから最大3件ずつ処理し、完成した分を順次表示できるようにする。
- ルート・履歴・月別集計・探索済み範囲・新しく走った道をまとめて更新する。過去記録の追加や削除に影響される後続記録も更新する。
- 実行予算が少なくなったら途中保存し、再開時刻を予約する。PCの起動は不要。

約5分は**更新確認の間隔**。大きなCSVの変換や予算待ちを含めた反映時間が5分以内という意味ではない。フォルダ一覧を2回確認してから処理するため、通常も検知から変換開始まで待ち時間がある。

```text
my-pace（MyPace共通管理フォルダ）
└─ running
   ├─ raw                ← CSV原本。ここだけを入力として探索する
   │  └─ *.csv           ← 現在の7件をそのまま使う。サブフォルダ可
   ├─ derived
   │  ├─ index.json       ← 参照先が全部完成してから最後に更新
   │  └─ ハッシュ名.json  ← 地図・履歴・集計・探索の表示用データ
   └─ system             ← 状態・キャッシュ。なければこのフォルダだけ作成
      ├─ checkpoint.json
      ├─ initial-index.json
      ├─ unit-page-*.json
      └─ catalog-*.json
       ↓ 既存の本人認証付き読み取り
現在のMyPace画面
```

`raw`・`derived`・`system` は `running` 直下の別々のフォルダにする。現在 `raw` にある7件をそのまま使い、原本の移動・変更・削除は行わない。`raw` と `derived` は既存のものを使い、見つからなければ停止する。`system` は既存ならそのまま使い、なければ作成する。各階層の名前は上記と完全一致・重複なしにする。

初回も再開時も、共通ルート→`running`→3つの兄弟フォルダをメタデータから特定し、本人所有・非共有・親子関係・IDの分離を確認する。再開時に同名の別フォルダへ勝手に切り替えない。`raw` が `derived` の中にある、出力が `raw` の中にある、同じIDが入力と出力を兼ねる、共有・移動・置き換えが起きた、といった場合は読み書きを進めない。

CSVの探索は `raw` を起点とする。ショートカットはたどらず、出力のフォルダIDを探索キューに入れない。`derived`・`system` は出力用の予約名とし、`raw` 以下でこの名前のフォルダを見つけた場合も `OUTPUT_FOLDER_IN_RAW` で止める（入力サブフォルダにはこの2つの名前を使わない）。中断時に保存した探索キューも、フォルダの現在の祖先を確認してから続行する。探索途中にサブフォルダが外へ移動された場合も、その先のCSV本文を取得しない。処理状態や完成JSONを読むための `system`・`derived` へのアクセスは、CSV探索とは別処理である。

フォルダ特定は共通ルートの確認と、ルート直下・`running` 直下の一覧取得を基本にする。Drive全体を検索せず、機能別のフォルダIDも設定しない。サブフォルダを深く細分化するほどCSV一覧の要求は増えるため、今の配置を維持すればよい。`english` や `app` は今回作らない。

## 本番取り込みの権限（前版から変更なし）

**初めて検証用から本番用へ切り替える際は、Apps ScriptのDrive書き込み権限を再承認する。すでに前版の本番用権限を承認済みなら、今回の修正で追加する権限はない。WebアプリのOAuth権限・クライアント・Vercel環境変数は変更しない。**

旧検証の `drive.readonly` + `drive.file` は、原本を読み、スクリプト自身が作成した検証ファイルを更新するためのものだった。今回は利用者が手動配置した本番 `index.json` の更新が必要。`drive.file` では、作成またはアプリへ明示的に許可されたファイルが対象となるため、手動配置ファイルへの書き込み権限を前提にできない。[GoogleのDriveスコープ説明](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)

そのため今回のマニフェストでは `https://www.googleapis.com/auth/drive` を使用する。**Googleが与える権限自体はDrive全体へのアクセスであり、フォルダ限定のOAuth権限ではない。** コード側で次を制限する。

- 元CSVと旧検証環境は読み取りだけ。
- 書き込み先は登録した `running/system` と `running/derived`。既存ファイルの更新はチェックポイント、キャッシュページ、登録した1個の `index.json` に限定。
- 書き込み直前に本人所有・非共有・親フォルダ・ファイル名を確認。
- 削除・移動・共有設定変更のAPIは実装しない。

この権限は前版 `a0e2825` と同じで、今回の `raw` 統一による追加の権限拡大はない。Google側の設定は開発側から変更していない。下の導入操作で内容を確認して承認する。外部公開用WebアプリとしてのApps Scriptデプロイは不要。

## 操作1：同じApps Scriptに新コードを用意する

1. **`NEW_CSV_PASS` を出した既存の「MyPace 差分更新検証」プロジェクト**を、前回と同じGoogleアカウントで開く。新しいプロジェクトにはしない。旧Script Propertiesとキャッシュを引き継ぐため。
2. 現在の `コード.gs` と `appsscript.json` を手元へ控える。現在のトリガーは検証終了後の0個のままでよい。他用途のトリガーがある場合、このコードはそれらを削除しない。
3. 下記で生成した `Code.gs` に、既存コードを**追記せず置き換える**。末尾に追加していたレポート関数も新コードへ混ぜなくてよい。プロジェクト設定のScript Propertiesは削除しない。
4. コード内を `MYPACE_PRODUCTION_CONFIG` で検索し、共通ルートIDだけ設定する。以前の `sourceFolderId` は項目ごと削除する。

```javascript
const MYPACE_PRODUCTION_CONFIG = {
  rootFolderId: 'my-pace共通管理フォルダのID'
};
```

`rootFolderId` はVercelの **`MYPACE_ROOT_FOLDER_ID` と同じ値**。`my-pace` フォルダを開いたURLの `/folders/` の後ろの部分を指定する。`running`・`raw`・`derived` のIDではない。入力と出力はコードがその配下から特定するので、`sourceFolderId` は不要。古い項目を残すと `ROOT_ONLY_CONFIG_REQUIRED` で止まり、無視して処理を始めることはない。IDや設定済みコードはGitHubへ載せない。

5. 初めて本番用コードを導入する場合は、プロジェクト設定で「appsscript.json マニフェスト ファイルをエディタで表示する」を有効にし、生成された `appsscript.json` を使う。すでに `a0e2825` の本番用マニフェストを設定・承認済みなら、そのままでよい。Cloudプロジェクト、WebアプリのOAuthクライアント、シークレットを変更する操作はない。

今回用意したキットはローカルの **`data/running-gas-production/Code.gs` と `appsscript.json`**。再生成する場合だけ、リポジトリで以下を実行する。生成時にはDriveへ接続しない。

```sh
npm run prepare:gas-production
```

設定済みキットを生成する場合は、上の1項目をJSONにした私有ファイルを `data/` 内へ置き、`npm run prepare:gas-production -- --config data/running-production-config.json` を使用する。出力先も `data/` 内に限定している。`build-info.json` のbuildIdは設定値を含めず、公開処理コードを識別する。

### 前版が `INPUT_OUTPUT_OVERLAP` で止まっていた場合

`a0e2825` のこのエラーは、本番用のROOT・チェックポイントを作成する前に発生する。コードを上の1項目の設定に差し替え、次の準備関数を実行すればよい。**Script Propertiesや検証済みキャッシュを削除しない。** 旧検証のやり直しも不要。

別の入力元で前版の本番準備がすでに成功していた場合は、`PROJECT_OR_CONFIG_CHANGED` で止める。異なる入力元の途中状態を、この構成の状態として自動採用しない。その場合もプロパティを消さず、状態を確認してから引き継ぐ。

## `READY` まで準備できている場合の今回の更新

**準備はやり直さない。** `gas-7f4917c7d6ce830888f4afa9` で `READY` になったScript Properties・チェックポイント・キャッシュをそのまま引き継ぐ。

1. 今回生成した `data/running-gas-production/Code.gs` を、準備したのと同じApps Scriptプロジェクトに貼り替える。`rootFolderId` は前回と同じ共通ルートIDを設定する。マニフェストと権限は変更不要。
2. Script Properties、`running/system`、`running/derived` を消さない。`prepareMyPaceRunningProduction` の再実行は不要。
3. `startMyPaceRunningProduction` を1回実行する。準備済みキャッシュを再利用し、未処理分の取り込みに進む。準備に使った内部計上時間も保持する。
4. Webアプリは今回のコミットのデプロイ完了後に開く。「記録」の横の状態表示を押すと、反映済みCSV数・残り・再開予定を確認できる。Vercelの環境変数変更や再ログインは原則不要。

開始時点で予算が足りなければ、開始指示を保持したまま待機し、自動再開する。初回の導入確認はこの操作にまとめる。合格済みの大容量・差分12段階・24時間検証は再実行しない。

## 画面で分かる取り込み状態

`running/derived/sync-status.json` に小さな状態通知を追加する。CSV・GPS・Drive ID・ファイル名を含めず、処理状況・件数・時刻・内部予算だけを保存する。`index.json` と独立しているため、予算待ちやエラーの通知で完成済みの地図を置き換えない。既存の準備済み状態には、開始時に状態ファイル用のIDを追加するだけで、変換キャッシュを作り直さない。

| 表示 | 意味 |
| --- | --- |
| 取り込み準備完了・開始待ち | 準備が完了し、自動処理はまだ開始していない |
| CSVを取り込み中 | 新規・変更CSVを変換中。完成分から反映 |
| 上限回復待ち | 内部予算待ち。詳細に自動再開予定（日本時間）を表示 |
| 更新確認済み | 最後の確認で未処理の追加・変更がない |
| 自動取り込みを停止中 | 停止操作済み。既存の表示は使用可能 |
| Googleへの接続を再試行待ち | 通信などの一時的なエラー。次の実行で再試行 |
| 取り込みの確認が必要です | 自動処理を止める必要のあるエラー。レポートのコードを確認 |
| 自動更新の状態が届いていません | 通常15分以上、または再開予定から15分以上、通知が更新されていない |
| 自動取り込みの状態は未接続 | 状態ファイルがまだない旧版。既存記録の読み取りは継続 |

画面を開いているときだけ約1分ごとに状態を読み取る。これはVercelからDriveへの小さな読み取りであり、Apps Scriptの変換を起動しない。表示データの世代が変われば新しい一覧・経路を読み込み、成功後に画面を差し替える。通信失敗時には前回の表示を保持し、再確認できる。ログアウト・認証失効時には個人データを消す。

Google側で実行開始前に上限到達・トリガー失敗となった場合や、権限変更により通知自体が書けない場合、処理側が理由を通知することはできない。この場合も、古い通知を「更新確認済み」と表示し続けず、状態の途絶・接続エラーとして示す。`showMyPaceRunningReport` の `statusWriteError` で通知書き込みの失敗も確認できる。

## 操作2：引き継ぎを準備する

関数メニューで **`prepareMyPaceRunningProduction`** を選び、1回実行する。初回は前述の権限を確認して承認する。

現在の `index.json` が `NEW_CSV_PASS` の完成目次と一致すること、全参照JSONが揃っていること、フォルダの所有・非共有状態を確認する。その後、`running/system` に現在の目次の控えと変換キャッシュを保存する。小さなキャッシュをページにまとめ、今後の読込要求とファイルの散らかりを減らす。

**この準備では元CSVの本文を取得せず、本番 `index.json` も変更しない。** 過去分のメタデータ一覧は取得する。処理が長ければ約5分後に自動再開し、準備が終わると自動で止まる。

状況を見るときは **`showMyPaceRunningReport`** を実行する。`status: READY` になれば引き継ぎ完了。`rawBytesRequested: 0`、`legacyCacheCopied: true` が目安。今回の配置なら `sources: 7` が目安。`sources` は `running/raw` 以下のCSV総数、`importedSources` は引き継げたCSV数、`pendingSources` は未処理の追加・変更CSV数。CSV数と画面のラン件数は必ずしも同じではない。

現在の7件のうち、検証済みCSVと内容が一致するものはキャッシュを再利用し、残りは開始後に取り込む。ここでコピー・移動・手動選択する必要はない。

## 操作3：継続更新を開始する

`READY` を確認したら **`startMyPaceRunningProduction`** を1回実行する。以降、`running/raw` 以下にある未処理の過去CSVも含め、順次取り込み、今後のCSVも自動検知する。

MyPaceのURLとGoogleログイン方法は現在のまま。今回の処理コードの導入のためにVercelを再設定・再デプロイする必要はない。画面の「記録を再読込み」またはブラウザーの再読み込みで、更新されたデータを見る。開きっぱなしの画面への即時プッシュ通知は今回追加していない。

**今回の実機確認はここまでを一度通せばよい。** `lastSuccessfulUpdate` が更新され、取り込んだ実記録が地図・履歴・集計に反映されることを確認する。過去分がたくさんある場合、全部の終了を待ってからでなく、最初の更新で確認できる。12段階・24時間監視のやり直しは不要。

| status | 意味・操作 |
| --- | --- |
| `PREPARING` | キャッシュ引き継ぎ中。自動で続く |
| `READY` | 引き継ぎ完了。開始関数を実行できる |
| `SETTLING` | 同じフォルダ一覧を次回も確認してから処理する |
| `PROCESSING` | 変換または表示JSONの保存中。前回の表示は維持 |
| `UPDATED` | 完成した目次を反映した。監視は継続する |
| `WATCHING` | 現時点の一覧に未反映の差分なし。約5分ごとに監視 |
| `BUDGET_WAIT` | 内部予算による休止。`nextRunAt` のUnixミリ秒以降に自動再開 |
| `INPUT_CHANGED_RETRY` | 処理中に入力が変わったため、次回一覧を確認し直す |
| `DRIVE_RETRYABLE` / `DRIVE_TRANSPORT_ERROR` | 一時的な通信失敗。自動再試行 |
| その他のエラー | 原因を `lastError.code` で確認。安全のため自動処理を停止 |

レポートは件数・時間・状態だけを短く出し、Drive ID、ファイル名、GPS、トークンを含めない。`lastSuccessfulUpdate` は停止操作で消さない。過去の合格結果用プロパティも変更しない。レポートにある実行時間・要求数・CSV要求量は、今回の継続処理を開始してからの累計。

## 停止・復帰

- **`stopMyPaceRunningProduction`**：この継続処理のトリガーだけ停止する。現在の表示、原本、キャッシュは維持。再開は `startMyPaceRunningProduction`。準備途中で止めた場合は `prepareMyPaceRunningProduction` で続行する。
- **`rollbackMyPaceRunningToInitial`**：継続処理を停止し、`index.json` を導入前の4件が表示されていた内容に戻す。原本やキャッシュ、追加済みJSONを削除しない。内部予算待ち中でも手動復帰できるが、Google側の権限・通信障害・実割当超過は回避できない。
- 目次がこの処理以外から変更されていた場合、知らない変更を上書きせず `CATALOG_CHANGED_EXTERNALLY` で停止する。`running/system/initial-index.json` が開始前の控え。困った場合は状況を共有し、目次を追加して同名2個にしない。

旧コードへ戻す必要がある場合は、先にこの処理を停止し、必要なら表示を復帰してから、控えた旧コードとマニフェストを戻す。旧検証の再実行は不要。古い検証ファイル・旧認証情報の削除は今回しない。`READY` 以降、通常の継続処理は移植先のキャッシュを使うが、旧環境の整理は実機で動作を確認してから別途行う。

## 予算と実用上の範囲

Googleの個人アカウントのトリガー総実行時間は90分／日、1実行6分。割当はユーザー単位で他スクリプトとも共有され、Googleの計上値をこの処理が正確に取得するAPIはない。[Googleの割り当て](https://developers.google.com/apps-script/guides/services/quotas)

このGoogleアカウントのApps Script枠は原則MyPaceで使う、という利用者の方針に合わせ、内部予算を**90分**に変更した。45分への独自の縮小は撤回する。準備・5分ごとの監視・CSV処理・状態通知を合算し、過去約24〜25時間で管理する。各実行を始める前に最大実行時間の6分を予約し、正常終了時には実測＋5秒で精算、強制終了した場合は予約を残す。したがって内部計上が約84分を超え、新たな6分を確保できなければ待機する。90分を使い切って途中保存できなくなることを避けるための余裕で、ほかの機能のために半分を確保する方針ではない。

URL Fetchも20,000回／日の枠を前提に、通常処理は19,800回まで使用し、200回を状態通知・途中保存などの余裕とする。待機では5分トリガーを止め、十分な時間枠・通信枠が空く時刻に再開を予約する。画面に表示する再開時刻は**内部予算上の予定**であり、Googleの実際の割当回復時刻を取得した値ではない。Googleの計上値や実行開始前の停止を完全には観測できず、90分以内を保証するものではない。

CSVは1MiBずつ読み、約90秒で次の作業単位へ進まず、続きを保存する。予算待ち中は5分ごとの処理を止め、再開用の単発トリガーを予約する。過去分が大量なら日をまたいで進む。1日に何件終わるかはファイルと地理的範囲によるので、3件固定の完了時間は保証しない。

データ形式・探索計算は合格済み実装を利用。表示JSONは1個128KiB以下、処理状態・キャッシュ単位は4MiB以下、入力CSVは既存処理と同じ1件512MiB以下。単一の重い計算を途中で分割する仕組みまでは追加していない。3回続けて進捗を保存できなければ `PROCESSING_UNIT_TOO_LARGE` で止める。無制限の履歴を実測済みとは扱わず、その場合は最後の正常表示を維持して作業単位を見直す。

原本のチェック・一覧取得はメタデータ、キャッシュの復元と既存表示JSONの整合確認はJSON本文を読む。「未変更CSVの本文を読まない」は、Driveへの通信が一切ないという意味ではない。
