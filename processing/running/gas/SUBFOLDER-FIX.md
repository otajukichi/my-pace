# 元CSVがサブフォルダ内にある場合の修正・再検証

2026年11月9日の診断では、元CSV3件とも内容・所有者・共有状態・ゴミ箱の確認は成立し、`parentMatches` だけが不成立でした。読み取り専用のDriveメタデータ確認により、3件とも次の構造で保管されていることを確認しました。

```text
設定した起点フォルダ
└─ CSV保管用のサブフォルダ
   ├─ 元CSV 1
   ├─ 元CSV 2
   └─ 元CSV 3
```

旧コードは直接の親だけを設定フォルダと比較していました。サブフォルダを認めない条件が停止の原因です。ファイル破損や実行アカウントの問題を示す結果ではありません。前回の成功した検証の時点からいつ配置が変わったかは、今回の確認では判断していません。

## 修正内容

元CSVの親をたどって、設定した起点フォルダに到達することを確認します。CSVの場所・内容・共有・権限は変更しません。起点フォルダの設定や参照用ハッシュも維持します。保存済みの検証状態と同じ設定のまま、今回の構造を扱えます。

対象外のフォルダは通過させません。途中の情報を取得できない場合、ゴミ箱内、フォルダ以外、循環や不正な親、16階層を超える場合も止まります。ショートカットの参照先はたどりません。所有者・共有・サイズ・MD5の確認は引き続き行います。

追加の通信は小さいフォルダ情報だけです。同じフォルダは1回の起動内で再利用するため、**今回の診断はCSV3件の情報＋親フォルダ1件の情報の計4回**です。CSV本文のダウンロードはありません。実際の検証では原本をコピーする前にこの確認を行い、5分ごとの変更なし監視には加わりません。各起動で再確認するため、親の情報を無期限に信用することもありません。

今回の変更は、既知の3件を検証用 `raw` へコピーする前の確認です。`raw` 内の差分検出や探索済み範囲の計算方式は変わりません。本番で任意のサブフォルダから新着CSVを探す監視機能とは別の工程です。

## 利用者の操作

1. **停止した同じApps Scriptプロジェクト**で、更新済みのローカル `data/running-gas-incremental/Code.gs` の全文を `コード.gs` に貼って保存します。マニフェスト・スクリプトプロパティは変更しません。
2. **`diagnoseMyPaceOriginalSources`** を1回実行します。この関数は読み取り専用です。
3. 次の結果を確認します。
   - `schema: 2`
   - `configurationMatchesRun: true`
   - 全体が `ORIGINAL_SOURCE_CHECKS_PASSED`
   - 各CSVの `directParentMatches: false`、`folderLocation.status: "DESCENDANT"`、`subfolderDepth: 1`
   - 各CSVの `checks.parentMatches: true`、`failedChecks: []`
4. 上の確認ができたら **`startMyPaceIncrementalProbe`** を1回実行します。既存の途中状態・予算を引き継ぎ、5分間隔のトリガーを再登録します。`myPaceIncrementalTick` を手で繰り返し実行する必要はありません。
5. 完了後は **`showMyPaceIncrementalProbeReport`** のJSONを返してください。判定の目安は `FUNCTIONAL_PASS`・`completedStages: 12` です。差分更新が通った後に、[24時間の待機コスト検証](INCREMENTAL.md)へ進みます。

診断結果が想定と異なる場合は、再開せず診断JSONを返してください。設定済みコードやDrive IDを送る必要はありません。

初回の開始から24時間を超えた実行には、既存の期限が適用されます。この場合は古いプロジェクトを停止したまま、新しい検証プロジェクトに更新済みキットを入れて初めから検証します。スクリプトプロパティや予算を書き換えて期限を延ばすことはしません。古い検証用フォルダや原本を削除する必要はありません。

`lastError` は最後に記録したエラーの履歴なので、再開後も以前の `ORIGINAL_SOURCE_CHANGED` が残る場合があります。現在の結果は全体の `status`・`completedStages`・各段階の `matched` で確認します。

## 開発側の検証

同じ構造の合成データで、読み取り専用診断が4回のメタデータ取得で通り、その後12段階すべてが参照結果と一致することを検証します。対象外・多段サブフォルダ・取得失敗・循環・深さ上限・ショートカット・ゴミ箱内の拒否、次の起動前に親を対象外へ移した場合の停止もテストします。Google上の差分処理の実測は、上記の再検証で確認します。

Driveの `parents` は直接の親フォルダを表します。[Google公式のファイル情報仕様](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)。フォルダ名ではなく親の関係を確認するので、同名の別フォルダを誤って受け入れません。
