# Apps Scriptで大きいCSVを3件処理する実測

> 2026-11-17時点：初回・差分・アイドル・新CSV・本人認証付き本番画面の確認まで完了。この文書は実施済みの手順資料です。次は [本番の継続取り込み](PRODUCTION.md)。過去の検証を再実行する必要はありません。

PCの常駐処理は運用として採用しません。Google側だけで自動処理できるかを、まず3件の実データで確認するための検証です。現在のアプリ、旧Apps Scriptプロジェクト、既存トリガー、元CSVは置き換えません。

この初回検証は、2026年11月9日に利用者がGoogle上で実行し、`TARGET_MET`・照合一致・時間切れなしと報告しました。以下は初回検証の操作資料です。**差分更新・24時間監視も合格と報告されました。新CSV確認も完了しており、次は[本番導入手順](PRODUCTION.md)を使ってください。** 初回の引き継ぎ資料は[こちら](HANDOFF.md)に残しています。

## 合格の目安

- 大きいCSVを3件、開始から24時間以内に処理し終える。
- 経路・速度・距離・ペース・区間・カレンダー・月間集計・探索済み範囲・新しく走った道の距離を、同じ一式として生成する。
- その結果が、同じ3件からローカルで生成した照合用データと一致する。
- 検証自身の累積実行時間は**60分以内**を目安にする。個人アカウントのトリガー総実行時間の制限90分／日に対して、30分の余裕を設ける。
- 1回の実行は90秒を超えたら次の作業単位に進まず、進捗保存・終了へ移る。合格判定では計測した最大実行時間240秒以内も確認する。1つの作業単位やGoogleの通信自体を途中で強制中断する仕組みではないため、実行履歴で6分の上限に達していないことも確認する。
- 通信は3,000回に制限する。元CSVの取得に限らず、途中保存・読み直し・最終確認を含めて数える。

Googleの90分は同じユーザーのほかのスクリプトも含む制限です。この検証でアカウント全体の残量は取得できません。既存処理の使用量も、実行履歴と合わせて確認します。公式の上限は変更される可能性があります。[Apps Scriptの割り当て](https://developers.google.com/apps-script/guides/services/quotas)

初回の対象は手元の大きい順の3件です。正確なサイズ・行数・GPS位置更新数は、Gitに含めない設定と測定結果に保存します。これは「最初の3件を一式にする」検証であり、長年の履歴へ毎日3件追加する性能まで証明するものではありません。その追加検証は初回測定後に行います。

## 動き方

1. Googleの定期トリガーで5分ごとに起動する。ブラウザーやPCを開いておく必要はない。
2. 元CSVを1MiBずつ取得し、時刻とGPSを読み取る。同じGPS位置の高頻度繰り返しをまとめる。
3. UTF-8の途中の文字、CSVの引用符・途中行、最後のGPS位置などを途中状態に保存する。次回は続きのバイトから読む。
4. 3件を処理したら、経路・分析・探索などを作る。完成した計算単位は再利用し、途中で止まっても続きから進む。
5. 出力ファイルを書き、読み直して内容を確認する。すべて完成したら最後にカタログを作る。
6. 集計した測定結果を `report.json` に保存し、この検証のトリガーを停止する。

ソースにはDrive ID、サイズ、MD5、1MiBごとのSHA-256を固定した検証用設定を使います。途中で原本が変わった場合は停止します。これは対象が既知の3件であることを利用した検証専用の照合です。実運用で新しいCSVを自動検知する部分は、このキットに追加していません。

新しい非公開フォルダをMy Driveの直下に1つ作り、途中状態と結果はそこだけに書きます。共有設定は変更せず、本人だけが利用できることを確認します。Webアプリとして公開する機能はありません。既存のGoogleプロジェクトやCSVには書き込みません。

## 用意済みのファイル

設定済みキットはGit対象外の `data/running-gas-probe/` にあります。

| ファイル | 用途 |
| --- | --- |
| `Code.gs` | 対象3件の設定を含む、貼り付け用コード。Drive IDを含むため非公開 |
| `appsscript.json` | Apps Scriptの実行環境と必要な権限 |
| `reference/` | ローカルで作った照合用データ。実GPSを含む |
| `config.json` | 元ファイルと照合値の私有設定 |
| `simulation-report.json` | 作成されている場合は模擬環境の結果。Googleの性能測定ではない |

コードの原本はこのフォルダの `probe-host.gs` と共通の変換モジュールです。個人のIDを入れずにGitに保存します。**`probe-host.gs` 単体をApps Scriptへ貼り付けても動きません。** 対象設定と共通モジュールをまとめた、ローカルの `data/running-gas-probe/Code.gs` を使います。

手元にある私有の選択設定と元CSVから再生成する場合は、次のコマンドです。

```bash
npm run prepare:gas-probe -- --manifest data/running-gas-selection.json
```

新しくGitHubから取得しただけの環境には `data/` がなく、このコマンドだけでは生成できません。今回の検証では、作業中のPCに用意済みのキットを使います。GitHubやチャットへ設定済み `Code.gs`・`config.json`・元CSV・`reference/` を載せる必要はありません。

## Googleで測定を始める操作

**既存のMyPaceプロジェクトは編集せず、新しい検証用プロジェクトを作ります。**

1. [Apps Scriptで新規プロジェクトを作成](https://script.google.com/home/start)し、名前を「MyPace ランニング3件検証」にする。元CSVを保存しているGoogleアカウントを使う。
2. ローカルの `data/running-gas-probe/Code.gs` を開いて全文をコピーし、新しいプロジェクトの `コード.gs` の中身に貼り付ける。
3. プロジェクトの設定で「appsscript.json マニフェスト ファイルをエディタで表示する」を有効にする。エディタで `appsscript.json` を開き、ローカルの同名ファイルの内容に置き換えて保存する。
4. エディタ上部の実行関数で **`startMyPaceThreeCsvProbe`** を選び、「実行」を押してGoogleの権限確認を進める。Google側のログに `SCHEDULED` が出れば開始できている。

これでタブを閉じ、PCを停止してもGoogle側の処理が進みます。デプロイ操作・公開URLの作成・PCでのサーバー起動は不要です。初回の定期実行までは数分待ちます。トリガーの起動時刻は厳密な時刻保証ではありません。[時間主導トリガー](https://developers.google.com/apps-script/guides/triggers/installable)

権限は元CSVを読む `drive.readonly`、このスクリプト自身が作った結果を扱う `drive.file`、Google APIへの通信、検証用トリガーの作成です。新しいデフォルトCloudプロジェクトでは、マニフェストに追加した高度なDriveサービスのAPIが自動で有効になります。既存の標準Cloudプロジェクトに付け替えた場合は別途APIの有効化が必要になることがあるため、まず新規プロジェクトのまま使います。[高度なサービス](https://developers.google.com/apps-script/guides/services/advanced)

## 結果を見る

My Driveの「MyPace ランニング処理検証 …」フォルダに `report.json` ができます。Apps Scriptで **`showMyPaceThreeCsvProbeReport`** を実行しても、位置情報を含まない集計結果をログに表示できます。

- `TARGET_MET`：3件が完成し、照合一致・24時間以内・実行時間の目安を満たした。
- `TARGET_MISSED`：出力は完成したが、時間の目安を超えた。
- `IN_PROGRESS`：次の定期実行で続行する。
- `DRIVE_RETRYABLE` / `DRIVE_TRANSPORT_ERROR`：通信が完了しなかった。次回は最後に保存した状態から再試行する。
- `SOURCE_*` / `REFERENCE_*` / `*_INTEGRITY`：入力の変化や照合不一致。検証を停止する。
- `BENCHMARK_BUDGET_REACHED` / `REQUEST_BUDGET_REACHED`：設定した予算に達した。自動で翌日に延ばして成功扱いにはしない。

自分で停止するときは **`stopMyPaceThreeCsvProbe`** を実行します。この検証が作ったトリガーだけを停止し、結果は消しません。再開は `startMyPaceThreeCsvProbe` です。計測予算や開始時刻はリセットしません。

`chargedExecutionSeconds` は計測した時間に終了処理用の余裕を足した自己計測です。実行が時間切れなどで途切れた場合、その回は最大6分を予約したまま数えます。保存されたレポートでは最後の実行の6分予約が残った上限値になる場合があり、`showMyPaceThreeCsvProbeReport` は終了後の計測値で表示します。これはGoogleの実使用量メーターではないため、Apps Scriptの「実行数」で実際の実行時間・失敗も合わせて確認します。

3件の初回測定が通ったら、履歴を保持したままの追加取り込み、記録修正・削除、長期の保存容量を次に確認します。これらが済むまでは検証用キットを本番の自動更新として扱いません。
